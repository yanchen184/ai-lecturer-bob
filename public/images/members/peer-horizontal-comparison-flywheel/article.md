# 讓 AI 判斷越用越準：一套專家定稿驅動的同儕橫向對照架構

我設計了一套系統，把「現場專家逐項判斷」交給 LLM 先做一版初稿，專家只要在上面刪改定稿。情境是這樣：有一群受評對象，每個對象要照一份很長的準則，逐項被專家看過、寫出「這項哪裡要改」的意見。我要做的，是讓模型把這件重複的事先跑一遍，把專家從「從零手寫」降級成「審閱定稿」。

這套系統有一個很硬的前提條件貫穿了所有設計決策：**這種現場專家的標註，又貴又稀少。** 一個專家看一個對象的一項要花時間，一年產不出多少筆高品質標註，你不可能像跑通用任務那樣灌幾萬條進去。整套架構就是繞著「標註稀缺」這個約束長出來的。

這篇拆解我怎麼設計它——檢索主鍵怎麼定、每個準則子項的生成怎麼分路徑、以及一套「專家定稿 → 去識別 → 回寫同儕池」的資料飛輪，讓系統越用越準，而且一次模型都不用重訓。

## 檢索主鍵：綁「類別 + 項目」，不綁個體

這套系統要回答的核心問題是：**「這一類對象，在這一個準則項目上，通常會被抓到什麼？」**

因為同類對象在同一準則項目上的缺失，是高度重複的。A 對象被指出的問題，B、C、D 大概率也有。這種橫向的同儕分佈非常稠密，而且即時——只要庫裡有同類對象的資料，隨時撈得到一整群。

所以檢索的主鍵，我定成**「類別 + 項目代碼」**，綁定的是「這一類對象的這一項」，而不是「某一個特定對象」。

個體碼在這套設計裡有一個明確而唯一的角色：**排除鍵**。檢索時把受評對象自己排除掉，避免拿它自己的舊資料跟它自己比——它不參與比對命中，只負責「把自己剔除」。

抽象成一段檢索邏輯，大概長這樣（語言無關的偽代碼）：

```python
def retrieve_peers(item_code, service_type, self_id, query, n=3):
    # 主鍵:同項目 + 同類別 —— 撈「這一類對象的這一項」
    where = {"item_code": item_code, "service_type": service_type}
    # 個體碼只當排除鍵:不要拿受評對象自己的資料跟自己比
    if self_id:
        where["entity_id"] = {"$ne": self_id}
    return vector_store.query(query, where=where, n_results=n)
```

主鍵這樣定，系統查的永遠是「某類別在某項目上的同儕橫斷面」。因為同一類別在同一項目上永遠有一整群同儕可以撈，這套檢索天生不怕「單一對象資料太少」——訊號來自整個同儕群，不來自任何一個個體。

## 三條路徑：命中、同儕提醒、留白

檢索定好之後，每一個準則子項的生成，我讓它嚴格走三條路徑之一。這是整個系統最關鍵的設計，因為它決定了「模型什麼時候可以講話、講到什麼程度」。

**路徑一 —— 命中（現場真的觀察到）**：如果這次現場的紀錄裡，真的有對到這個子項的內容，就從紀錄裡萃取事實，產出正式的「改善事項」。這是唯一一條系統敢下斷言的路徑，因為它有本次的一手依據。

**路徑二 —— 未命中，但同儕池有料（同儕提醒）**：如果這次現場沒提到這個子項，但同類對象在這一項上常被抓到某些缺失，系統產出一條**措辭克制的提醒**，標題明確寫成「同類機構常見（非本次觀察，建議複查）」。它不是斷言「你有這個問題」，而是「你的同儕常在這裡出事，回頭複查一下」。這條路徑的價值，是把稀缺的同儕經驗變成一張檢查清單。

**路徑三 —— 未命中，且同儕池也空（留白）**：既沒本次觀察、又沒同儕資料可對照，系統就**留白**，回一句「本次未涉及本項，且無同儕資料可對照」。這條路徑存在的意義，是**明確禁止模型硬掰**。沒有依據時，空白比一句漂亮的廢話有價值得多。

三條路徑背後是同一條核心原則：**斷言只留給有一手依據的命中路徑；沒有依據的，要嘛降級成提醒、要嘛閉嘴。** 這條原則把「模型的話語權」跟「證據的等級」死死綁在一起。

## 飛輪收口：專家定稿才是權威標籤

檢索加三路徑，做到的是「這一次產得聰明」。真正讓系統**越用越準**的，是收口那一步——**專家定稿回寫**。

系統產完初稿，專家在上面刪改、定案。我把這份**定稿**（不是 AI 的原始輸出）當成唯一的權威標籤，做三件事：

1. **去識別**：把定稿裡的真實人名換成代稱、真實機構名換成代稱。因為這筆資料接下來要跨對象被別人檢索當範例，不能把可識別個資帶進池子。
2. **回寫同儕池**：依「類別 + 項目」把去識別後的定稿寫進向量庫。
3. **餵未來同儕**：從此，同類別的其他對象在同一項目上檢索時，就會撈到這筆專家定稿過的高品質範例。

這一步把「一次性的格式產生」變成「持續累積的觀察資產」。權威來源永遠是人的定稿，AI 只是把專家的判斷放大、複製到同儕之間。設計上我特別堅持一點：**進池的是專家定案後的版本，不是 AI 初稿**——飛輪餵的是被人背書過的高品質標籤，不是模型自己產的、可能有錯的原始輸出。這決定了飛輪是越轉越乾淨，還是越轉越髒。

整個飛輪長這樣：

```kroki:mermaid
flowchart LR
    A["現場紀錄"] --> B["三路徑生成初稿"]
    B --> C["專家刪改定稿"]
    C --> D["去識別<br/>人名→代稱<br/>機構名→代稱"]
    D --> E["依 類別+項目<br/>回寫同儕池"]
    E -."未來同類對象<br/>橫向檢索"..-> B
    C --> F["本次交付"]
    style C fill:#ffe6a7,stroke:#d4a017
    style E fill:#a7d8ff,stroke:#1778c4
```

黃色那一格是整套系統的信任錨——**權威標籤來自專家定稿，不是 AI 原始輸出**。藍色那一格是飛輪的閉環——**定稿去識別後回流，餵下一批同儕**。

## 用檢索而不用重訓來「越長越準」

這套系統的「越用越準」是靠檢索實現的，不是靠重訓模型。我用**固定權重的 embedding 模型 + 向量檢索**：定稿去識別後算成向量丟進庫，新樣本進池的**當下**就能被檢索到，零訓練、零部署延遲。飛輪的轉速等於「專家定稿的速度」。

這樣設計是因為它剛好對上「標註稀缺」這個前提。向量檢索的「學習」是連續的、即時的、可解釋的——你隨時能打開庫看它到底撈了哪幾筆範例出來，每一筆珍貴的定稿一進池就發揮作用。在標註本來就湊不出批量的場景下，「不重訓也能長」正是我要的性質：把手上每一筆稀缺的高品質標籤，即時放到最大。

## 兩個關鍵的措辭與安全取捨

**同儕提醒的語氣邊界**：路徑二的措辭我刻意壓得很克制。同儕資料很容易讓專家被錨定——系統若把「同類常見」寫得太肯定，專家明明本次沒觀察到，也會傾向認定受評對象有這個問題。所以我把措辭定成「同類常見、建議複查」的提醒語氣，並在標題明寫「非本次觀察」，把它跟命中路徑的斷言在版面上徹底分開。**同儕資料的定位是提醒複查，不是替代觀察**，這條邊界寫進生成規則裡。

**去識別的保守取捨**：中文人名沒有可靠的通用抓法，所以我的去識別走「稱謂錨點」策略——只在明確的職銜脈絡下才視為人名替換。這是刻意選「寧漏不誤傷」：寧可漏掉一兩個、也不把正文裡的一般名詞誤傷掉（誤傷會把意見改到語意變形）。因為這筆資料要進池當別人的範例，錯抹一個字的代價，遠低於把一句話的語意改壞。

## 這套架構的適用邊界

這套「同儕橫向對照」有一個明確的成立前提：**同類對象夠多、而且回訪週期遠大於決策週期**（對象隔很久才回來一次，你不可能靠單一對象自己的歷史累積出訊號）。在這種資料形狀下，訊號只能來自橫向的同儕群，橫向對照才是對的解。

反過來，如果你的對象回訪很頻繁、單一對象自己就能累積出稠密的時間序列（例如每天都有新資料的同一個用戶），那訊號本來就在個體自己身上，這套橫向架構就不必套——硬套只會撈到一堆不相干的同儕。**架構跟著資料形狀走，不是反過來。**

## 一句話收束

當你要用 LLM 取代稀缺的現場專家判斷，這套架構的三根柱子是：

- **檢索綁「類別 + 項目」**，讓訊號來自整群同儕，個體碼只當排除鍵；
- **生成嚴格走三路徑**（命中才斷言、同儕只提醒、無料就留白），把話語權綁死在證據等級上；
- **飛輪只燒專家定稿**——去識別後回寫同儕池，餵未來同類對象。

三根柱子疊起來，系統會越用越準，而且你一次模型都不用重訓。
