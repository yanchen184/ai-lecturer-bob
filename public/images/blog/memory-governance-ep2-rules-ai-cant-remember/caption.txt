🧠 為什麼你寫的 AI 規則,它每次都做不到?

你寫了一堆 CLAUDE.md:
「不要重複造輪子」
「動手前先查 memory」
「對自己嚴格」

每條都對,Claude 點頭認同,然後該違規還是違規。

問題不在它「沒看」 — CLAUDE.md 它每個 session 都吃進去。
問題在它「看了不知道什麼時候該動」。

—

你寫的是「描述性原則」:
- 不要重複造輪子(什麼算重複?)
- 注意分類(什麼時候注意?)
- 對自己嚴格(嚴格的判準在哪?)

LLM 真正會跟的是「程序性 SOP」:
- 寫 memory 前必跑 `ls ~/.claude/memory/`
- 對照既有檔的 3 種狀態決定動作
- 寫完必加 `## 相關` 區塊,沒加 = 違規

差別不在更詳細,在把「判斷外化」。

—

改寫公式:
描述狀態 → 觸發條件 + 強制動作 + 違規判斷

舊:「避免過度設計,保持簡單」
新:
- 觸發:設計層決策時
- 動作:給 2-3 選項配 trade-off,預設選最簡
- 違規:看到自己寫「以後可能需要」立刻刪那個方案

—

為什麼 LLM 對程序性反應特別好?

訓練資料分佈決定的。
LLM 看過大量 step-by-step 技術文件,
「先 A 再 B 最後 C」是它最熟的路徑。

抽象指令「要有 sense」「對自己嚴格」
在訓練資料裡多半出現在無效的職場 feedback —
LLM 學會的回應是:點頭認同 + 不知道下一步。

【Memory 治理 EP2|為什麼 AI 記不住你寫的規則】

EP1 講完整理 memory,我馬上問自己一個問題:
「過 3 個月,會不會又長回花朵狀?」

幾乎一定會。因為我整理的是「結果」,沒整理「行為」。

—

翻自己半年內寫的 CLAUDE.md 行為規範,看到一堆這樣的句子:

「不要重複造輪子,動手前先查 memory」
「寫 memory 時注意分類,避免同主題開新檔」
「跨檔的關聯要記得 link」
「對自己嚴格,看到違規要主動修正」

每一條我都認同。每一條我都看過 Claude 違反。

問題不在它沒看 — CLAUDE.md 每個 session 都吃進去。
問題在它看了不知道「什麼時候該動」。

—

描述性 vs 程序性,差在三個層面:

▌觸發條件
舊:模糊(「注意」「記得」「避免」)
新:明確(「寫新 memory **前必跑**」「結尾**必須有**」)

▌動作
舊:抽象(「分類」「link」)
新:可執行(`ls ~/.claude/memory/`、加 `## 相關` 區塊)

▌違規判斷
舊:主觀(「太花」「太多」)
新:客觀(「沒 ls 就動筆」「沒 `## 相關` 區塊」)

—

為什麼 LLM 對程序性指令反應這麼好?

這不是玄學,是訓練資料分佈決定的。

LLM 接受過大量 step-by-step 數據 —
技術文件、Stack Overflow、教科書、code review。
「先 A 再 B 最後 C」是它最熟的格式。

「要有 sense」「對自己嚴格」這類抽象指令,
在訓練資料裡多半出現在無效的職場 feedback —
LLM 學會的回應是「點頭認同 + 不知道下一步」。
